## 0. 事实基线：2.0 到底有什么

写 3.0 之前先把 2.0 摊开看。下面每一行都对应代码里的真实位置，功能设计不能绕过它们。

| 能力 | 代码位置 | 现状 | 对 3.0 的影响 |
| --- | --- | --- | --- |
| 单击台词 | finish_left_action 329–334 → show_dialog 573 | 从 SAYINGS 随机取一句，5 秒自动关 | 台词必须从「全局随机」改为「按状态取」 |
| 台词池 | SAYINGS 22–25 | 只有 2 条，都是初代梗 | 3.0 至少 20 条并分组，否则新玩法会露馅 |
| 拖拽 | left_drag 321–327 / move_inside 466 | 拖动时钳制在屏幕内 | 可挂「被拖拽」情绪、挣扎、音效 |
| 缩放 | resize_by_right_drag 341–347 | 140–700 px | 所有道具尺寸必须按 size/290 比例算，禁止写死像素 |
| 自由飞行 | roam 276 / flight_step 229 | 惯性转向 + 多屏 union 探测 | 夜间降速、停靠边缘都要在这条路径上改 |
| 双击 | double_click 363–372 | 命中躯干 0.18–0.82 × 0.45–0.83，50% 概率咬人 | 咬人升级只有这一个入口 |
| 咬人 | start_bite 389 / bite_approach 401 | chase → carry → return 三阶段，Esc 可中断 | 升级只需插入 struggle 阶段，不必重写 |
| 动画 | animate 295 / prepare_wings 113–151 | 60 帧预生成；翅膀多边形形变 + 下半身剪切形变 | 新服装会同时破坏「翅膀多边形」和「y=350 髋部接缝」 |
| 气泡 | show_dialog 573 / position_bubble 597 | 独立 Toplevel，纯黑 #111111，白字 12pt，宽 ≤300 | 单行实际容纳约 16 个汉字，文案有硬上限 |
| 设置 | show_settings 507 | ttk 面板，4 个开关 + 1 个滑块 | 3.0 新增项会挤爆面板，需要分组或滚动 |
| 持久化 | config_path 33 / load 654 / save 670 | settings.json 只有 x,y,size,moving,cross_screen,always_on_top | 3.0 要加 hood / mask / mood / inventory / album |
| 能力缺口 | — | 无音频、无道具实体、无状态机、无真透明、无文件拖放 | 这些就是 3.0 的主要成本 |

### 0.1 三条硬约束（先说死，后面所有设计都受它约束）

1. **不许新增窗口数量。** 气泡已经是一个额外 Toplevel，柠檬、面具、画框如果各开一个窗口，就会出现"跟脸不同步、拖拽时错位、置顶顺序乱"的经典 bug。全部画在同一个 canvas 上，作为额外 item。
2. **一切尺寸按比例。** 唯一例外是 mouth_offset（384 行）写死了 (123,188)，因为嘴要咬鼠标。新增锚点建议统一写成「290 画布坐标 → 按 size/290 换算」。
3. **#010203 是色键，不是 alpha。** 见 7.4。这条决定了 3.0 的美术只能是硬边 + 深描边，不能做柔光。

### 0.2 顺手发现的一处口径不一致

README 第 11 行写「双击切换静止 / 自由飞行」，但代码 363–372 的双击是**咬人**（50% 概率）。3.0 上线前建议统一口径，否则新玩家会照 README 操作，然后被叼走鼠标。

## 1. 照片元素拆解表

拆解原则：照片里的每样东西，只能转化成三类之一——(a) 一个可玩动作，(b) 一个可独立绘制的美术层，(c) 一个 UI / 场景隐喻。三类都不占的，不进 3.0。

| # | 视觉元素 | 照片里的事实 | 转化为（具体到能画 / 能做） | 级别 |
| --- | --- | --- | --- | --- |

### 1.1 明确不转化的东西

| 元素 | 为什么不转化 |
| --- | --- |
| 拿手机的手、露出的人脸 | 照片里有真人，桌宠里出现人手会破坏「福塔是生物」的幻觉 |
| 地砖、墙面色差 | 只提供环境光参考，不进入素材 |
| 镜子本身的反射 | 「镜中另一个福塔」听起来好玩，但需要第二个窗口 + 同步，成本远超收益，记为下一版本彩蛋 |

### 1.2 拆解得到的一句话

照片真正提供的不是「一套衣服」，而是**一个动作（遮脸）+ 一个时间（深夜）+ 一个空间（柜子与门）**。3.0 应该围绕这三点做，而不是照抄衣服细节。

## 2. 3.0 主题命名与世界观

三个候选，分别押「时间」「动作」「空间」。

### 候选 A：绒绒夜航（Plush Night Flight）

- **一句话世界观**：福塔白天是桌角的一团毛，入夜就披上连帽睡衣，把桌面当停机坪，叼着柠檬在窗口之间巡夜——你不睡，它也不睡。
- **核心情绪词**：暖、困、偷偷、陪。
- **为什么成立**：
  1. 2.0 唯一持续存在的运动是自由飞行（roam / flight_step），「夜航」把这段代码叙事化，**不需要新机制**。
  2. 照片本身就是夜间室内暖光，色调可以直接沿用。
  3. 睡衣是「一张图多图层」的换装，美术成本可控（见第 4 节）。
  4. 可扩展：夜航日志、航线、停靠点都能往后长。
- **风险**：白天缺少主题支撑，容易变成「只有晚上才好玩」。

### 候选 B：遮脸计划（Project Hood）

- **一句话世界观**：福塔坚信只要挡住脸就不算社死——兜帽拉满、面具戴正、柠檬挡嘴，谁也别想看清它。
- **核心情绪词**：害羞、嘴硬、虚张声势。
- **为什么成立**：
  1. 照片的核心动作就是遮脸自拍，动作即玩法，转化率最高。
  2. 一个「挡」的手势可复用三种情绪（害羞 / 拒绝 / 得意），性价比极高。
  3. 反差感对「坏萌」人设是加强而不是稀释：越凶的脸越怕被看清。
- **风险**：主题偏「一个小动作」，撑不起整个 3.0 的叙事，更像一个玩法而不是一个版本。

### 候选 C：福塔的深夜寄存柜（Night Locker）

- **一句话世界观**：蓝色储物柜是福塔的工位，木门是它的出租屋，儿童画是上一任租客留下的——你的桌面只是它夜班的一格。
- **核心情绪词**：寄居、收藏、旧物、一点点孤独。
- **为什么成立**：
  1. 把停靠（柜格）、相册（寄存）、便签（租客留言）、收纳（挂包）四个「收藏型」功能收进同一个世界观。
  2. 美术上蓝 + 棕 + 粉对比强，截图好看。
- **风险**：需要额外场景资产（柜体、门、画框、挂包），是三个候选里美术最贵的。

### 2.1 对比与推荐

| 维度 | A 绒绒夜航 | B 遮脸计划 | C 深夜寄存柜 |
| --- | --- | --- | --- |
| 与 2.0 机制的契合 | 高（复用飞行） | 中（复用单击/双击） | 中（复用停靠，但停靠还没做） |
| 美术新增成本 | 中（一套睡衣 + 三态帽） | **低（一个帽子层）** | 高（场景资产） |
| 叙事延展性 | 高 | 低 | 中 |
| 记忆点 | 中 | **高** | 高 |
| 一句话能讲清 | 能 | **能，且更好笑** | 偏文艺，需要解释 |

**推荐：A「绒绒夜航」作为 3.0 主标题，把 B「遮脸计划」作为 P0 旗舰玩法的名字，C 作为 3.1 的美术主题包。**

理由：A 提供版本框架（时间轴 + 飞行 + 换装），B 提供第一个能立刻玩到的手势，C 的资产可以后补。三者不是互斥选项，而是「版本名 / 玩法名 / 美术包」的三层关系。宣传口径建议写成：

> 福塔 3.0 · 绒绒夜航
> 副标题：遮脸计划

### F1 兜帽升降与遮脸害羞（P0 · 低）

**触发**
- 右键菜单第一项「帽子」，三态循环：放下 → 半戴 → 拉满。
- 点击头顶绒球：轻点切换「半戴 / 放下」。
- 自动触发：连续 3 次单击都没有拖拽，第 4 次点击前自动变「半戴」（它先害羞了）。

**反馈**
- 动画：抬起 6 帧 / 落下 5 帧（约 220ms / 180ms），落定后绒毛回弹 2px 一次。
- 遮脸态额外：身体左右各歪 1px、2 帧循环，像在憋气。
- 气泡：遮脸态所有台词加「闷声」处理——两侧加引号，字号不变但位置下移到下巴（复用 position_bubble 的 tail 计算）。
- 音效（若有）：布料摩擦 120ms，短、闷、不循环。

**与 2.0 的衔接**
- 复用现成的「布尔开关 + 存配置」模式（moving / cross_screen 那套）；settings.json 新增 hood 字段，三态用字符串。
- 冲突处理：遮脸时双击不触发咬人，改为「戳帽子」，回一句嘴硬台词。命中区判定在 double_click 363 之前插一个 if。
- 注意：兜帽态会改变头部视觉重心，双击命中区（370 行的 0.45–0.83）需要按 hood 状态上移。

**成本与风险**
- 美术：3 个帽子层 + 6 帧过渡。代码：一个枚举 + 菜单项 + 一个 if。
- 风险：遮脸时玩家看不到表情，容易误判为卡住 → 必须保证 8 秒后自动降到半戴。

### F2 怪兽面具系统（P1 · 中）

**触发**
- 右键「面具」子菜单，从已解锁里选；或「随机戴一个」。
- 拖拽面具图标到福塔脸上（后续版本）。
- 夜间彩蛋：23:00 后 5% 概率自己戴上一个，戴着的面具每天不同。

**反馈**
- 动画：0.8 → 1.06 → 1.0 的弹入（4 帧），戴稳后抖两下。
- 台词池切换：每个面具一套 6 条「人格台词」，语气不同（怪兽=凶、柠檬=酸、地球=忧、小狗=黏、空白=面无表情）。
- 咬人时面具的嘴跟着张开（假牙联动），这是最值得做的一处细节。

**与 2.0 的衔接**
- 面具是第 5 层（见 7.2），夹在脸与兜帽之间；render_frame 的缓存 key 增加 mask_id。
- 与 F1 叠加：mask + full hood = 只剩一团粉色，配合「福塔不在」台词，是最强的一帧。

**成本与风险**
- 美术：6 个面具 × 5 层（底 / 毛边 / 眼洞 / 牙 / 高光）。文案：6 × 6 = 36 条。
- 风险：面具多了会变成「皮肤商店」，偏离桌宠的陪伴感 → 建议面具只能通过「事件」解锁（深夜出现、连续投喂、找到柠檬），不做货币。

### F3 柠檬玩偶：投喂 / 叼走 / 找回（P0 · 中）

**触发**
- 柠檬平时待在桌面右下角的一个小碟子上（福塔的「食盆」）。
- 单击柠檬 → 福塔飞过来咬一口（投喂）。
- 连续投喂 3 次 → 福塔吃饱，**自己把柠檬叼走**藏到随机角落（窗口边缘、任务栏上方、屏幕四角之一）。
- 找到（把柠檬拖回碟子 / 点击它）→ 福塔回来「抢」，抢输后给一句服软台词。

**反馈**
- 投喂：咬合 3 帧 + 脸颊鼓包 6 帧 + 4 颗碎屑粒子，气泡「酸的。再来。」
- 叼走：柠檬挂在嘴上（跟随 mouth_offset），飞行速度提升 15%，像偷到东西。
- 找不到：超过 45 秒，福塔左右各看一次（头转 2 帧 ×2），气泡提示方向（「左边。我什么都没说。」）。

**与 2.0 的衔接**
- 道具位置用 move_inside / covered 保证不会藏到屏幕外——这条逻辑 2.0 已经有了，直接复用。
- 柠檬画在同一 canvas 的额外 item（不新开窗口），坐标是「世界坐标 - 窗口坐标」，拖窗口时要跟着重算。
- 库存状态进 settings.json：lemon = {x, y, state: "dish" | "held" | "hidden", fed: 0}。

**成本与风险**
- 美术：柠檬 4 组帧（静置 / 被叼 / 被咬 / 抛出）。代码：一个状态机 + 一个额外 canvas item。
- 风险：如果它把柠檬藏到「另一个显示器」，玩家会真的找不到 → 限制在当前屏，且 30 秒后给提示。

### F4 夜间作息与打瞌睡（P0 · 低）

**触发**

**反馈**
- 打瞌睡：眼皮下垂 3 帧、身体前后 1.5px 呼吸、头顶浮起 Zzz 三个字符（每 2 秒一个，上浮 24px 淡出——注意不能淡出，见 7.4，改成逐帧消失）。

**与 2.0 的衔接**
- 飞行速度系数：roam 里给 speed 乘 0.6（夜间）。
- **关键坑**：animate 304 行的 paused 分支决定了「静止时不推进 frame_index」。所以 2.0 的静止模式是完全不动的。夜间呼吸动画必须让 idle 也推进帧，否则会像 PPT。这一步要重构成「位移」与「帧」解耦。

**成本与风险**
- 成本低（一套睡眠帧 + 时间判断），风险全在那个 paused 分支上。建议先做「静止也呼吸」，再做睡眠。

### F8 双击咬人升级（P0 · 低）

**反馈（新流程）**

**成本与风险**

### 4.7 帧数与内存预算（重要）

现有代码在初始化时预生成 60 帧（prepare_wings 131–151），每帧 290×436 RGBA：

    290 × 436 × 4 = 505,760 B ≈ 494 KiB / 帧
    494 KiB × 60 ≈ 29 MiB

如果 3.0 有 6 个状态组、每组 60 帧，就是 174 MiB，启动会明显变慢、内存爆掉。建议：

| 状态组 | 帧数 | 单帧 | 小计 |
| --- | --- | --- | --- |
| 静止立绘 | 1 | 494 KiB | 0.5 MiB |
| 飞行 / 行走 | 60（沿用） | 494 KiB | 29 MiB |
| 打瞌睡 / 睡眠 | 12 | 494 KiB | 5.8 MiB |
| 兜帽过渡 | 6 | 494 KiB | 2.9 MiB |
| 面具 / 柠檬 / 特效 | 各 ≤6 | 494 KiB | 约 9 MiB |
| **合计预算** | | | **≤ 60 MiB** |

两条规矩：
1. **按需生成**，不要一次性把所有状态都烘出来；用 LRU 上限 120 帧（现有 render_cache 已经这么做了，照抄思路）。
2. **2× 资产只用于静止立绘**。580×872 单帧是 1.93 MiB，做成 60 帧就是 116 MiB，绝对不行。

## 5. 文案

### 5.1 调性规则

- 沿用「比我萌的没我坏，比我坏的不存在」的底：**先示弱半拍，再反转成坏**。
- 结构公式：观察 + 反转。「你忙你的，我忙我的。/ 我忙着等你。」
- 不用：嘤、啾、抱抱、贴贴、气鼓鼓、呜呜。这些会把「坏」稀释成「软」。
- 不用 emoji。Tk 的彩色 emoji 支持很差，会渲染成黑白或方框（现有气泡是 Microsoft YaHei UI 12pt）。
- 标点只用：，。、～？—— 和引号。不用连续感叹号。
- **单行 ≤16 个汉字**，每条 ≤2 行。这是气泡宽度 300px 的硬上限。
- 遮脸态的台词加「」表示闷声。

### 5.3 台词数据结构建议

        "hood_full":[...],   # 遮脸态

        "lemon_missing":[...],

选择逻辑：场景优先，场景池为空时回落 idle。同一句台词 10 分钟内不重复（一个 8 条的环形缓冲就够）。

### 6.4 心情值

mood 0–100，初始 60，存 settings.json。

| 事件 | Δmood |
| --- | --- |
| 单击 | +2 |
| 摸头（F9） | +8 |
| 投喂（F3） | +6 |
| 找回柠檬 | +10 |
| 被拖拽超过 1 秒 | −3 |
| 咬人被挣脱 | −2 |
| 5 分钟无交互（09:00–22:00） | −1 |
| 5 分钟无交互（22:00–06:00） | −0.5 |

阈值：≥60 用 HAPPY 池，26–59 用正常池，≤25 强制 SULK + 酸话池。mood 不显示成数字，只通过姿势和台词体现——这是「宠物」而不是「养成游戏」的分界线。

### 6.5 优先级与伪代码

同一 tick 里多个状态可同时成立时，按优先级取最高：

    PRIORITY = [BITE, DRAG, SHY, SULK, HAPPY, CURIOUS, FLY, DOCK, DOZE, SLEEP, IDLE]

    def state_tick(now):
        idle = now - last_interaction
        mood = clamp(mood, 0, 100)
        night = hour >= 22 or hour < 6

        if biting:                  return BITE
        if dragging:                return DRAG
        if shy_until > now:         return SHY
        if mood <= 25 and idle > 60:return SULK
        if mood >= 60:              return HAPPY
        if idle > 180 or night:     return SLEEP if idle > 180 else DOZE
        if idle > 45:               return DOZE
        if flying:                  return FLY
        if docked:                  return DOCK
        return IDLE

注意：优先级列表里 SHY 高于 SULK —— 害羞是「想被看见」，生气是「不想被看见」，前者更该被优先表达。

### 6.6 与渲染的关系

每个状态对应一组帧（见 4.7），状态切换只换帧组，不改坐标。唯一会改坐标的是 DRAG（跟鼠标）、BITE（跟光标）、DOCK（贴边），这三者本来就由 2.0 的几何代码负责，不要重写。

转换必须有过渡：至少 3 帧的过渡，不允许硬切。硬切会让整个桌宠显得廉价。

### 7.4 Tkinter 兼容注意

这是整个 3.0 最容易翻车的地方，单独说清楚。

**现状**：窗口用的是 -transparentcolor（46 行）+ 纯色背景 #010203（19 行）。这是**色键**，不是 alpha 通道。render_frame（164 行）把缩放后的 RGBA 贴到 (1,2,3,255) 的画布上，任何半透明边缘像素都会和近黑色混合，然后……不被键掉，于是留下黑边。

**结论：3.0 只能是硬边美术。**

三种「软边」方案与取舍：

| 方案 | 做法 | 代价 | 建议 |
| --- | --- | --- | --- |
| 假软边 | 描边宽度随 size 在 1–2px 变化，用深色过渡制造柔和感 | 几乎为零 | **推荐，先做这个** |
| 预乘近背景色 | 把边缘像素预乘到 #010203 附近 | 一定出现黑边，且随缩放变化 | 不推荐 |
| 真 alpha | 改 WS_EX_LAYERED + UpdateLayeredWindow，每帧提交 HBITMAP | 等于重写整条渲染管线 | 3.x 再评估 |

**其他必须知道的兼容点**：

1. **paused 分支（304 行）**：静止模式完全不推进 frame_index，所以呼吸、Zzz、眨眼全部不会动。想做好「夜间打瞌睡」，必须先把「帧推进」与「位移」解耦，否则看起来像卡死的图片。
2. **命中区写死比例（370 行）**：加了帽子后视觉重心上移，双击会打空。建议命中矩形随 hood 状态偏移，而不是改成一个更大的框（会误触）。
3. **动画性能**：60fps 下每帧重建 PhotoImage 会掉帧。现有 render_cache 上限 24（169 行）是对的，新增状态必须沿用「按状态 LRU」，不要每个状态各存一堆。
4. **气泡字体（587 行）**：Microsoft YaHei UI 12pt，宽 ≤300。彩色 emoji 在 Tk 里会渲染成黑白或方框，文案里禁止 emoji；想表达情绪用文字或 1–2 个全角符号。
5. **DPI**：多屏不同缩放时，size 是逻辑像素；拍立得截图会跨 DPI。第一版只支持单屏，别一开始就做多屏适配。
6. **淡出做不了**：色键窗口不能逐像素改 alpha。Zzz、心形、碎屑的消失一律改成「逐帧缩短/直接消失」，不要写 alpha 动画。

## 8. 落地顺序与风险

### 8.1 建议顺序

| 阶段 | 内容 | 产出 |
| --- | --- | --- |
| 1 | 重构「帧推进与位移解耦」+ 硬边睡衣立绘 | 静止也会呼吸的睡衣福塔 |
| 2 | F1 兜帽三态 + F4 夜间作息 | 第一个可玩的「手势 + 时间」 |
| 3 | F3 柠檬 + F8 咬人升级 | 第一个「道具 + 暴力」循环 |
| 4 | F2 面具 + F9 绒球 | 表情差分体系完成 |
| 5 | F5 停靠 + F6 拍立得 | 场景化，截图传播点 |
| 6 | F7 / F10 / F11 | 长尾内容 |

### 8.2 三个最大的风险

1. **主题过载**：照片元素太多，很容易什么都做一半。守住 P0 的四个功能，其余全部延后。
2. **状态机蔓延**：11 个状态 × 6 个台词池 × 每池 6 条，维护成本会失控。建议所有台词走 5.3 的 dict，状态只决定 key。
3. **渲染性能**：60 MiB 的帧预算必须写进验收标准，否则做到第 4 个状态就会卡。

### 8.3 一句话总结

3.0 不需要新玩法系统，只需要把 2.0 已经有的三个动作——**飞、咬、被拖**——放进一个「夜里穿着睡衣、怕被看清、偷偷藏柠檬」的角色里。
